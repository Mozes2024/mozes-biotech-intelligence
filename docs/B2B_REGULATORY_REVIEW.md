Confirmed against production main `c0aa1af489efbf01ea79e194621530f3c04d90ec`.
This branch starts independently from that main, without B2a or unmerged A5 PR #35.

## Writer and consumer audit

- `intelligence_store.DDL` creates `v2c_regulatory_review`: review ID, ticker,
  source URL, observed time, reason and original statement payload. No resolution,
  reviewer, authorization or outcome-decision field exists.
- `regulatory_lifecycle._review` is the sole application writer, using
  `INSERT OR IGNORE` with an evidence/reason-derived ID. `apply_guidance` sends
  missing source identity, mismatched issuer, future publication, outcome claims,
  unresolved application, unsupported/past target and same-day conflict here.
- `refresh.scan_watch_universe_regulatory` invokes `apply_guidance` and counts
  review results; its filing progress cursor is not a review decision.
- `financial_context.operation_health` counts every stored review row;
  `payload_v3.build` exports that count under `intelligence_v2c`.
- `financial_context_ui.js` previously displayed only that count, described as
  FDA identity checks. No existing item reader or approval/rejection consumer was
  found in `mozes`, `scripts`, `tests` or `web`.

## Minimal read-only presentation

A separate `regulatory_review.review_queue` reader exports every retained row
under a new `regulatory_review` payload field. It performs SELECTs only, does not
create schema, and works with SQLite `query_only=ON`. No existing count, writer,
decision semantics or alert eligibility changes.

The separate system-page overlay displays issuer/application identity only when
independently supported by source CIK, watch identity and a verified catalog
application. Its existing application status is separate from the pending claim.
Each claim remains `REVIEW_REQUIRED`, never a confirmed outcome. Exact source
reference, reason code, full original evidence and stored timestamps are visible.
Non-SEC/malformed references are escaped text, not executable links. Unsupported
payloads retain raw evidence. All rows remain visible without a silent cutoff.

Filing/publication time, original retrieval time and queue observation time are
distinct. Missing original retrieval/event times remain unknown: queue observation
does not substitute for retrieval, and SEC filing time is not outcome time.
The existing writer does not always capture original retrieval metadata; this
presentation cannot retroactively establish it.

Rows have no reconciliation state. Therefore this is a list of **retained review
claims**, not proof that every row still needs action or that an application has
never been resolved elsewhere. It deliberately does not auto-hide a row because
another version/application state now exists. Opening a source is actionable for
human investigation; accepting/rejecting a claim is not supported here.

## Regression evidence and preservation

Before implementation, the six new presentation tests failed: exported payload
contained no review items, no read-only reader existed, and no UI existed.
After implementation, seven focused tests passed, including exact evidence and
publication timestamps, missing dates, issuer mismatch/unverified application,
malformed payload/identity fields, duplicate review suppression, all 106 fixture
rows remaining visible, query-only operation and unchanged database dumps.
Production script-chain tests additionally verify visible claims, escaped hostile
text and no notification generated by rendering.

PR #38 list/history safeguards and B1 overlays are exercised through the unchanged
production script chain. Existing sources, event IDs, histories, review rows,
ACKs and receipts are not altered, acknowledged or replayed by this reader/UI.
No production database, workflow, migration, flag, deployment or live source scan
is part of this change.

## Separate decision-workflow design — not authorized or implemented

Safe decisions need a separately approved storage and authorization design:

1. An append-only decision record referencing review ID, exact evidence hash,
   verified source/application, decision/reason, authenticated actor and decision
   time. Preserve the original review row and explicitly represent superseded
   decisions; do not overwrite the evidence.
2. A protected server-side reviewer role and explicit reconciliation permission.
   The public/static browser must never receive write credentials. Require CSRF
   protection, audit attribution and a human confirmation with the exact evidence.
3. Transactional stale-evidence/application-version checks and retry idempotency.
   A changed claim or conflicting source must require a fresh decision. An approval
   alone must not set outcome time from filing time or create alert/ACK/receipt
   side effects. Promotion/delivery requires its own approved policy and tests.
4. A separately reviewed schema migration, audit/backup/rollback boundaries and
   adversarial authorization/concurrency tests before activating any write route.

No new tables, controls, routes or mutation code from that design are included.
GO for review of this presentation PR; HOLD for any decision/promotion workflow.
